# Pixel rewrite import candidate

This candidate replaces the previous Pixel implementation with the prepared
deterministic rewrite. It is for review; it is not a release or a compatibility
claim. Issue: [Pixel #1342](https://github.com/Pixel-CLI/pixel/issues/1342).

## Provenance

- Pixel baseline: `1490b54df3cf67cf16f7c217e707ce7aad4ebf54`.
- Source: [rto-cli/rto#70](https://github.com/rto-cli/rto/pull/70), branch `codex/pixel-identity`.
- Source commit: `39040563a3a01b4d39df2c635c23b39394f20fc4`.
- Source tree: `c1f4787d78b35e9caa92c1e403dd62c7ce31646e`.
- Only committed Git objects were imported. The source working tree, Git
  metadata, caches, ignored files and local environment settings were not copied.
- The existing local checkpoint `d7d1484fa128461e13c021641ce3a17b64952955`
  and integration commit `616c93d4dfd07b4c3cfe2c3b6324e52a4a0192d9`
  remain in the original Pixel checkout. Neither is an ancestor of this branch.

`rto-pixel-2026-10-24.json` lists every preserved file, its mode and its
baseline Git blob ID. The candidate contains 559 unchanged source files,
one source checker with the integration adjustment below, 144 preserved
Pixel files, and four added manifest/report/changelog/test files.

## Preservation exceptions

| Root or file | Files | Reason |
| --- | ---: | --- |
| `README.md` | 1 | Existing Pixel README, as explicitly requested |
| `website/` | 117 | Existing Hugo site, templates, data, assets and tool pin |
| `docs/examples/` | 23 | README WebPs and Hugo-mounted MP4/JPEG media |
| `docs/motion/prompt-submit/` | 2 | README-linked recording source and explanation |
| `.github/workflows/pages.yml` | 1 | Existing site build and deployment configuration |

These files remain byte-and-mode identical to the Pixel baseline. The Hugo
mount of `../crates/pixel/Cargo.toml` still resolves in the rewrite, so no
site template or configuration change was needed. Source-only site files
under these roots are deliberately omitted.

The sole source adaptation is `scripts/ci/check-spdx.py`: the three preserved
source/build files already attributed to Pixel retain that attribution. An
explicit three-path allowlist recognizes their existing copyright and still
requires the MIT license header. `scripts/test-preserved-spdx.py` verifies
those paths pass, while unknown attribution, missing license and Pixel
attribution on other paths fail. No attribution was rewritten and no `--fix`
was run.

## Copy verification

The import script checked both archives against `git ls-tree -rz`, including
blob IDs and executable/symlink modes, before writing the isolated worktree.
It then compared all imported and preserved files with their respective Git
objects. It also checked that 1,346 old baseline-only project paths were absent,
the destination Git pointer and original checkout were unchanged, and the
checkpoint remained reachable.

The committed tree must contain exactly the source tree outside the declared
preservation roots, the preserved baseline files, the one checker adaptation
and the four additional paths listed in the JSON manifest. No old engine
crates were retained as compatibility code.

## Known documentation differences for final review

The existing README and site were deliberately retained, not rewritten to
advertise unmeasured results for the new engine.

- README local links absent from the candidate: `docs/manual-setup.md`,
  `docs/github-actions.md`, `docs/bench/decide-bakeoff.md`, and
  `docs/bench/vs-xerj.md`. The three linked WebPs are preserved and resolve.
- Legacy examples such as `pixel prepare-repo .`, `pixel doctor .` and
  `pixel brief … .` need reconciliation with the rewritten command surface.
  Git mutation commands and historical API compatibility are explicit non-goals
  in `specs/thesis.md`.
- The README/site historical performance figures describe previous Pixel
  versions; comparative acceptance of this candidate is not established.
- Hugo reads the source crate's candidate version `0.0.0` for its metadata
  and footer; no release version was invented for the transfer.
- The imported CI/workflow set replaces the previous set, including removal
  of the old board-sync workflow. Existing GitHub branch protection and
  repository settings were not changed; required check-name expectations
  must be reconciled before any merge.

## Validation boundary

The source PR reports Actions run
[40124624759](https://github.com/rto-cli/rto/actions/runs/40124624759)
was refused before any steps because of GitHub billing/spending limits.
Those jobs are **UNVERIFIED**, not passing and not test failures. That does
not block preparation of this destination candidate, as explicitly requested.

Destination copy checks and lightweight checks are reported in the PR body
with their commands and results. Full Rust compilation/tests, host installation,
comparative benchmarks and release validation were not run locally. No source
PR was merged, no package/release was published, no HOME install was performed,
and the original Pixel main branch was not pushed.
